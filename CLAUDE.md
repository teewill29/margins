# Margins

A personal songwriting notebook. Each page pairs a writing exercise (word grid, object writing, cut-up and others) with a ruled writing pad and voice memos. The app detects when I've used an exercise word in my lyrics, including changed forms like burned → burn. One user (me), used mostly on my phone as an installed PWA. Working name: Margins.

## Read these first
- `docs/SPEC.md`: every screen and feature
- `docs/WORDS.md`: the word banks, grid recipes and draw rules, plus every other exercise's content source. **Its rules are unit tests.**
- `docs/DETECTION.md`: word matching levels and syllable counting, with test cases. **These cases are unit tests.**
- `docs/DATA_MODEL.md`: database tables and fields
- `docs/DESIGN.md`: tokens, fonts, components
- `docs/PHASES.md`: build order and what "done" means for each phase
- `design/mockups/*.dc.html`: visual reference for each screen. They use a canvas runtime (`support.js`) that isn't in this repo, so read them for layout, copy and styles. Don't try to run them.

## Hard rule: nothing paid
No paid APIs, services or subscriptions. No server code. Everything runs on the device. Libraries must be free and open source (MIT, BSD, ISC, Apache or similar). If a feature seems to need something paid, stop and note it in the Open questions section below instead of building it.

## Stack
- Vite + React + TypeScript (strict)
- React Router
- Dexie (IndexedDB) for all data, including audio blobs, stored on the device
- vite-plugin-pwa: installable, works fully offline
- Plain CSS with CSS custom properties (no Tailwind, no UI kit). One `tokens.css`.
- Fonts self-hosted through `@fontsource` packages (no Google Fonts requests, so it works offline)
- `compromise` for word roots, plus our own irregular-forms table (see DETECTION.md)
- `syllable` for syllable counts
- `cmu-pronouncing-dictionary`, used only by the build script that makes the word bank (rhyme keys), never shipped to the client
- JSZip for backup export and import
- Vitest for unit tests
- Hosting: Vercel Hobby (free), static build only. Framework preset Vite, build `npm run build`, output `dist`.

## How to work
- Build one phase at a time, in the order of `docs/PHASES.md`. Don't start a phase until the previous one meets its acceptance criteria.
- Detection, syllables, the seeded random generator and every draw rule live in pure functions under `src/lib/` with no React or database imports. Write the tests from WORDS.md and DETECTION.md **before** the code.
- All exercise content (word bank, objects, lines, titles, dice, character tables) is static JSON in `src/data/`, generated by `npm run bank`. You write the source lists yourself in Phase 2 and 3. Every line, title and prompt must be original. Never copy lyrics, titles or lines from real songs, poems or books.
- Dates are local calendar dates as `YYYY-MM-DD` strings. Never use UTC midnight math for days. The daily grid seed depends on this.
- Mobile first: design at 390px wide, touch targets at least 44px, nothing important hidden behind hover. Respect safe-area insets.
- Never hardcode a color: use tokens.
- Keep UI copy plain and short. No em dashes in UI text.
- Losing a song idea is the one failure this app can't have. Never delete data without an undo or confirmation, and keep the backup flow working in every phase.
- When a phase is done, update the Commands section above and add a line to the Progress log below.
